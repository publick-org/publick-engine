{{ _("Measures") }}

{{ _("Time to acknowledge") }}
{{ _("Submission to staff acknowledgment. Since only staff can acknowledge, this is the most direct measure of the city's response. Requests never acknowledged are left out, so the share that were acknowledged is shown alongside it. Many requests are closed without being acknowledged first.") }}
{{ _("Time to close") }}
{{ _("Submission to the latest close. If a request was archived without a close time, the archive time is used. Requests still open are left out, so the typical time to close is for closed requests only.") }}
{{ _("No update in over a year") }}
{{ _("An open request whose last change on SeeClickFix (a status change, comment, or edit) was more than a year ago. Some may have been fixed and never closed; others may never have been handled. The data doesn't show which. They still count as open.") }}
{{ _("Typical (median)") }}
{{ _("Half took less time, half took more. Unlike an average, a few very old requests don't skew it.") }}
{{ _("1 in 10 took over") }}
{{ _("The 90th percentile: how long the slowest requests take.") }}
{{ _("Ward") }}

  • {{ _("A closed request isn't always a fixed problem. Duplicates and requests outside the city's responsibility also get closed.") }}
  • {{ _("Some departments use SeeClickFix more than others.") }}
  • {{ _("Ward differences reflect how often people report problems, not only how the city responds.") }}
  • {{ _("Recent months will change as requests close.") }}
  • {{ _("A repeat location isn't always the same problem. It can be a problem that came back, a fix that didn't hold, or a separate problem nearby.") }}
